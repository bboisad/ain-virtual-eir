# 记忆机制与云端存储：周末会议演示

目标是在 5–7 分钟内展示：项目记忆从哪里来，相关历史如何被找回，记录如何在云端持久保存，以及旧版本如何受到保护。演示使用虚构数据。

## 演示前准备

- 本次交付目标日期：2026 年 11 月 20 日（周五）。此日期是交付目标，不是自动执行任务的预约。
- 在 `docs/CLOUD_DEPLOYMENT.md` 的验收表中填写实际网址、部署版本和实测结果。没有实际验证的项目继续写“待执行”。
- 提前打开云端服务，完成共享密码登录。准备浏览器A和无痕窗口B，分别登录 Alice、Bob，打开 Campus Loop。
- 准备一段文字文件，内容为虚构访谈或实验笔记。只使用演示数据。
- 需要自由对话演示 AI 记忆时，先确认模型可用。没有模型密钥时可以展示检索来源和预设流程，但要明确“当前为脚本演示”，不能声称已验证模型回答。

## 1. 用一分钟说明你做了什么

可用口述：

> 原型原本会读取最近对话、每日摘要和项目记录。我这部分补充了相关历史的检索和来源标注，让被近期窗口排除的信息仍有机会进入导师上下文。云端部分把项目和版本放进数据库，把上传文件放进私有文件桶；不同设备读同一个项目，保存时检查版本，避免旧内容悄悄覆盖新内容。

用一张图说明“结构化记录＋近期对话＋相关历史→导师上下文”，再用一张图说明“浏览器→Streamlit→数据库／文件桶”。当前项目记录优先于历史说法；找到旧对话不代表它已成为客户证据。

## 2. 展示记忆与来源，约两分钟

1. 先在主导师聊天发送虚构内容：`The library kiosk experiment is owned by Bob.`。
2. 打开右上角 Menu → **Project memory**，在搜索框中输入 `library kiosk`。展示检索到的原话、日期与成员来源；此步骤不需要先发送30条消息，也不需要真实AI密钥。
3. 说明这个面板用于查看项目已保存的内容和来源，检索命中不会自动提升证据等级。
4. 如需展示真实模型在长对话后仍能接续记忆，另行准备超出最近30条窗口的历史案例，再问 `Do you remember our library kiosk experiment?`。只有实际接入模型并运行过，才把模型回答这一项计为通过。
5. 将回答与当前 Action Plan 对照；如果历史说法与当前任务不同，导师应说明时间和变化，不能直接把旧说法当成最新状态。

同一天的长对话和超过最近7个摘要日期的内容都有相应离线检索测试。真实模型演示应另外准备和验证。检索测试通过只能证明内容进入上下文；还要单独检查真实模型是否正确使用它。

## 3. 展示跨设备保存，约一分钟

1. 浏览器A在 Action Plan 添加一项虚构任务，例如“云端展示：检查商家付费测试”。
2. 浏览器B刷新或重新打开项目，确认出现同一任务。
3. 关闭A、重新登录，确认任务仍存在。
4. 可在 Supabase 后台只展示该项目的版本号和更新时间，避免展开不必要的聊天内容。

这证明应用读取的是共享持久数据，不能只用同一个浏览器里切账号来证明跨设备保存。

## 4. 展示文件，约一分钟

1. 上传准备好的虚构笔记，先保存，保持原有“团队决定何时让导师阅读”的流程。
2. 从另一个会话打开该文件并下载。
3. 比较内容；展示私有桶配置，并说明原文件与提取文字独立于项目JSON存储。

## 5. 展示并发保护，约一分钟

使用 `python scripts/cloud_check.py --write-test` 的真实输出展示以下过程：两个读取者取得同一版本，A保存成功，B使用旧版本保存被拒绝；再读取项目，A的结果仍在。

如果用浏览器演示，应事先排练，因为页面刷新可能重新读取最新版本，无法稳定制造冲突。不要为了演示刻意关闭版本检查。解释冲突处理会提示重新读取，不会自动合并两人的修改。

## 会上可交出的材料

- 实际可访问的部署网址，以及演示密码的私下传递方式。
- 可运行源代码、依赖文件、数据库初始化SQL、部署配置。
- 记忆流程图、云端架构图、测试结果和仍未通过的项目。
- 部署／恢复说明、数据和账号的维护负责人。

## 当前状态如何表述

部署配置、迁移脚本和离线测试属于交付材料；真实云端运行属于单独的验收结果。在没有真实账号配置和实际部署结果时，应写“已准备云端部署包，待配置账号并验收”，不能写“已上线”。

这版共享密码和演示账号适合小组展示。正式接入学生或教师的真实身份和资料前，需要补充学校认可的身份认证、服务端用户权限和数据管理决定；相关能力不能凭演示账号选择器推断为已完成。
